# 부모로 하우스 스타일

부모로의 결과물은 **흰 종이 위에 하늘색 하나**로 보여야 한다. 참조 원본은
`references/tone-reference.md`에 정리돼 있고, 토큰은 `references/tokens.css`를
그대로 복사해서 쓴다.

## 0. 만들기 전에 30초

1. 이 화면은 **정보 / 혜택 / 힐링** 중 무엇인가 → 1번 3톤에서 바탕색이 결정된다.
2. 사람이 모이는 화면인가 → `references/community-patterns.md`를 먼저 읽는다.
   홈·단어방·프로필처럼 **부모가 서로를 보는 화면은 전부 해당**된다.
3. 카피는 **반말**인가 → `references/voice.md`
4. 마지막에 `references/anti-patterns.md`의 체크리스트를 눈으로 훑는다. 하나라도
   걸리면 그건 부모로가 아니라 "AI가 만든 화면"이다.

## 1. 3톤 시스템 — 이게 부모로 디자인의 전부다

부모로는 색을 많이 쓰지 않는다. **바탕색 세 개**로 콘텐츠 성격을 구분하고,
나머지는 회색조다.

| 톤 | 바탕 | 쓰는 곳 | 글자 |
|---|---|---|---|
| **흰색** — 정보 | `--card` `#FFFFFF` / `--cream` `#FCFAF6` | 실전 정보, 대화, 목록, 본문 | `--ink` |
| **하늘** — 혜택·브랜드 | `--sky-bg` `#EAF5F9`, 강조는 `--sky` `#4FA9C7` | 혜택, 브랜드, 강조 블록, 커뮤니티 | `--ink` + `--sky-d` |
| **네이비** — 힐링·새벽 | `--navy` `#141A2E` 그라디언트 | 새벽 시리즈, 힐링, 새벽 모드 | `#fff` + `--moon` |

피드·리스트에서 네이비가 **대각선/체스판처럼 띄엄띄엄** 박히면 리듬이 생긴다.
연속으로 두 개 놓지 않는다.

> 하늘색 규칙 — `--sky #4FA9C7`는 **면·아이콘·테두리 전용**이다(흰 배경 대비
> 2.7:1). 하늘색 **글자**는 반드시 `--sky-d #2E7E9A`(4.6:1, AA 통과)를 쓴다.
> 이거 하나 틀리면 접근성이 무너진다.

`--blue #2B6FFF`는 브랜드색이 아니다. **숫자·링크·순번 배지**에만 쓰는 기능색이다.
파랑이 하늘색보다 넓은 면적을 차지하면 잘못 만든 것이다.

## 2. 타이포 — 부모로 티가 가장 크게 나는 곳

```
font-family: "Pretendard Variable", Pretendard, -apple-system, sans-serif;
letter-spacing: -.02em;   /* 본문 기본 */
word-break: keep-all;     /* 한국어 필수 — 단어 중간에서 끊지 않는다 */
line-height: 1.55;        /* 기본 */
```

- **제목은 800**, 라벨·수치도 800. 700 이하 제목은 부모로처럼 안 보인다.
  본문 강조 `<b>`는 600~700.
- **제목 자간은 더 좁게**: `-.03em` ~ `-.05em`. 클수록 더 좁게 조인다.
- **행간은 반대로 간다**: 제목 `1.3~1.45`(붙임) / 본문 `1.7~1.85`(넉넉히).
  이 대비가 부모로의 리듬이다.
- **폰트 크기는 0.5px 단위를 쓴다**: `14.5px` `13.5px` `12.5px` `11.5px` `10.5px`.
  14/13/12로 딱 떨어지는 스케일은 템플릿처럼 보인다.
- 본문 한 줄은 `max-width: 640~660px`.

### Pretendard를 못 불러오는 곳 (Artifact/목업)
Artifact CSP는 `fonts.googleapis.com`만 허용해서 jsdelivr의 Pretendard가
**조용히 실패**한다. 그럴 땐 대체 스택을 쓰고, 그렇다고 적어둔다.

```html
<link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600;700;800&family=Noto+Sans+KR:wght@400;500;700;900&display=swap">
```
```css
font-family: Inter, "Noto Sans KR", "Pretendard Variable", sans-serif;
```
Noto Sans KR은 900이 Pretendard 800 자리다. 대체 시 제목 weight를 900으로 올린다.
Next.js 앱(`src/app/layout.tsx`)은 CSP 제약이 없어 진짜 Pretendard를 쓴다.

## 3. 형태

- **모서리**: 큰 블록 `24px` / 카드 `16px` / 작은 카드 `14px` / 배지·버튼 `9~12px`
  / 칩 `6~7px`. 전부 같은 radius를 쓰면 위계가 사라진다.
- **큰 블록엔 테두리를 넣지 않는다.** 회색 바탕(`--bg #F4F5F7`) 위에 흰 카드를
  올려 경계를 만든다. 테두리(`--line2`)는 **작은 카드·일러스트 프레임**에만.
- **그림자는 떠 있는 것에만**: `0 6px 18px rgba(15,25,50,.1)`. 블록에는 없다.
- 여백: 블록 안쪽 `30px 26px`, 모바일 `24px 18px`. 블록 사이 `14px`.
- 가로 스크롤 카드 열은 `scrollbar-width:none` + `::-webkit-scrollbar{display:none}`.

## 4. 카피 — 반말이 기본

부모로는 **반말로 말한다**. 사용자에게 보이는 UI 문구(버튼·안내·토스트)는 존댓말
"~해요"체지만, 콘텐츠·설명·카드 문장은 반말이다. 자세한 건 `references/voice.md`.

- 시그니처는 **🩵 하나**. 다른 이모지를 섞지 않는다. 문장 끝에 하나만.
- 지어낸 숫자를 쓰지 않는다. 확인 안 된 금액·비율은 "동네마다 다름"이 정답이다.
- 의료·안전은 경험 공유 선을 지킨다. 판단이 필요하면 "병원 가는 날이야"로 넘긴다.

## 5. 커뮤니티 — 화면에 사람이 보여야 한다

부모로는 정보 앱이 아니라 부모들이 하루 종일 떠드는 곳이다. 자세한 건
`references/community-patterns.md`. 자주 놓치는 것만 옮기면:

- **홈은 대시보드가 아니라 대화 목록**이다. 카톡처럼 마지막 메시지가 미리보기로
  보인다. 배우지 않아도 쓸 수 있어야 직관적이다.
- **안읽음 숫자를 쓰지 않는다.** 새 대화는 점 하나. 숫자는 **나를 부른 것**
  (내 질문의 답·채택·멘션)에만 붙인다. 숫자 배지는 그 자체로 피로다.
- **방마다 주인이 있다.** 각 단어방 상단에는 그 달 리더가 채우는 **리더 카드**가
  있다 — 인사말·자기 글·링크 1개. 접힌 상태가 기본이고, 파는 것이면 홍보 표시가
  붙는다. 전체 1등 자리는 하나뿐이지만 리더 자리는 단어 수만큼 있어서, 공구·인스타
  하는 부모가 현실적으로 노리는 목표가 된다.
- **가볍게 참여할 길**을 항상 같이 둔다. 답변은 부담이니 공감 한 번으로 끝나는
  길을 옆에 붙인다.
- **랭킹을 앞세우지 않는다.** 홈에 순위표를 놓지 않고, 방 안에서 리더가 자연스럽게
  보이게 한다.

## 6. 만들고 나서 — 이것부터 확인

`references/anti-patterns.md`를 열어 체크리스트를 훑는다. 특히 자주 걸리는 것:

- [ ] 섹션 제목 앞에 이모지를 붙였는가 → 뗀다
- [ ] 모든 카드가 같은 radius + 같은 그림자인가 → 위계로 나눈다
- [ ] 보라~파랑 그라디언트 히어로인가 → 네이비 또는 흰 바탕으로
- [ ] 하늘색을 글자에 썼는가 → `--sky-d`로
- [ ] 폰트 크기가 전부 정수인가 → 0.5px 스케일로
- [ ] 카피가 존댓말 설명문인가 → 반말로, 짧게
- [ ] 화면에 사람이 안 보이고 숫자만 있는가 → 아바타·이름·마지막 말로
- [ ] 안읽음 숫자 배지를 달았는가 → 점 하나로. 숫자는 나를 부른 것만
- [ ] 단어방에 주인의 자리가 있는가 → 리더 카드가 빠지면 방이 빈 공간이 된다
