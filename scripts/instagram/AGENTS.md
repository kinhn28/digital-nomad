# 부모로 인스타 카드뉴스 — 에이전트 가이드

이 디렉터리에서 작업할 때는 이 문서를 먼저 읽는다.
`@bumoro.kr` 인스타그램 피드용 **1080×1350 PNG 카드 + 캡션**을 만드는 파이프라인이다.

> 상위 `AGENTS.md` 규칙(Next.js 관련)은 그대로 유효하다. 이 문서는 그 위에 얹힌다.

---

## 1. 부모로는 어떤 계정인가

**부모로(@bumoro.kr)** — 바쁜 부모를 위한 정보 계정.
슬로건은 "받을 수 있는 건 다 챙겨요. 부모 마음까지도".

- 독자: 0~3세 아이를 키우는 부모. 신생아~돌 전후가 가장 두껍다
- 다루는 것: 정부 지원금 · 육아 실전 팁 · 맘카페썰 · 부모 경제 · 꿀템
- 목소리: **옆집 엄마가 알려주는 톤.** 전문가가 설명하는 톤이 아니다
- 절대 하지 않는 것: 배우자·시댁 등 특정 대상 비난, 진료 지침 흉내,
  확인 안 된 금액·날짜 단정, 아이 얼굴 노출

브랜드 토큰(색·워드마크)은 `brand.mjs`. 손대지 않는다.

---

## 2. 명령 두 가지

| 명령 | 장수 | 구조 |
| --- | --- | --- |
| **한장** | 1장 | 표지만. 정보 본문은 전부 캡션이 진다 |
| **여러장** | 5~8장 | 표지 + 넘버링 내지 3~6장 + 엔딩. **넘버링 필수** |

장수를 말해 주지 않으면 소재의 정보량으로 정한다.
팁이 2개 이하이거나 사실 한 줄로 끝나는 주제는 한장으로 간다.
**항목 수는 2~6개 사이에서 주제가 요구하는 만큼만.** `3가지`로 고정하지 말 것.

---

## 3. 전체 작업 순서

```
소재 발굴  →  덱 작성  →  이미지 생성  →  렌더 + 검증  →  캡션  →  전달
 (4절/5절)    (6·7절)      (8절)         (9·10절)       (11절)
```

1. 소재를 고른다 — 카톡 대화 파일(4절) 또는 뉴스·최신 이슈(5절)
2. `decks.mjs` 에 덱을 추가한다. **문구가 먼저다.** 이미지는 문구를 따라간다
3. 슬라이드마다 영어 `scene` 을 쓰고 이미지를 생성해
   `assets/photos/gen/<덱ID>-NN.png` 로 저장한다
4. `node generate.mjs --deck=<ID>` 를 돌린다
5. **검증 4종이 전부 조용해야 한다.** 하나라도 뜨면 문구를 고치고 다시 돌린다
6. `captions.md` 에 본문/첫 댓글/해시태그를 적는다
7. `hooks.md` 사용 기록에 오프닝 패턴을 남긴다
8. `public/instagram/<ID>.zip` 과 캡션 전문을 사용자에게 전달한다

## 4. 소재 발굴 A — 카톡 대화 파일

사용자가 카카오톡 대화 내보내기(zip)를 준다. 절차:

1. 임시 디렉터리에 풀고 `.txt` 를 모은다
2. 메시지 파싱 정규식:
   `^(\d{4})\. (\d{1,2})\. (\d{1,2})\. (오전|오후) (\d{1,2}):(\d{2}), (.+?) : (.*)$`
3. **이전에 본 메시지와 중복 제거.** 같은 방을 여러 번 내보내므로
   본문 문자열 기준으로 걸러야 새 내용만 남는다
4. 주제 키워드 클러스터로 세어 본다 (수면·이유식·분유·기저귀·접종·변비·
   어린이집·복직·유모차·돈 등). 건수만 보지 말고 **각 클러스터에서 20~30줄을
   샘플링해서** 실제 알맹이가 있는지 눈으로 확인한다
5. **14절의 발행 기록과 대조해 이미 나간 주제를 뺀다**
6. 남은 것을 순위 매겨 사용자에게 제시하고 고르게 한다

### 대화를 카드로 옮길 때

- **방에서 실제로 쓰인 말을 그대로 쓴다.** 지어낸 말보다 훨씬 세다
  (예: "쪽쪽이 6개 돌려막기" → 표지 "지호네는 쪽쪽이가 여섯 개래")
- 이름·지역·병원명·특정 가능한 정보는 **전부 지우고 일반화**한다
- 등장 이름은 가상으로 돌려 쓴다: 준수 · 서연 · 지호 · 하윤 · 도윤 · 시우
- 한 사람의 사연을 그대로 옮기지 않는다. 여러 사람 말을 묶어 일반화한다

## 5. 소재 발굴 B — 뉴스 · 최신 이슈 리서치

정책·지원금·리콜·계절 이슈처럼 **시의성이 소재인 것**은 검색으로 가져온다.

### 무엇을 찾는가

| 유형 | 예 | 카드가 되는 조건 |
| --- | --- | --- |
| 정책·지원금 | 양육수당 개편, 바우처 확대 | 시행일과 대상이 확정됐을 것 |
| 마감 | 근로장려금, 접종 무료 기간 | 남은 날짜가 2주 이내 |
| 계절 | 독감 유행, 명절 연휴 진료 | 지금 부모가 실제로 겪는 중 |
| 안전 | 육아용품 리콜, 성분 이슈 | 식약처·소비자원 등 공식 발표가 있을 것 |
| 제도 변경 | 어린이집 비용 항목 변경 | 부모 지갑에 직접 닿을 것 |

**부모의 돈·시간·불안 중 하나에 직접 닿지 않으면 카드로 만들지 않는다.**

### 리서치 절차

1. 검색으로 후보를 모은다. 오늘 날짜 기준으로 유효한지 먼저 본다
2. **1차 출처를 반드시 확인한다** — 보건복지부 · 질병관리청 · 국세청 ·
   식약처 · 각 지자체 공고. 언론 기사만 보고 카드를 쓰지 않는다
3. 금액 · 날짜 · 대상 연령 · 소득 기준을 **1차 출처 원문과 대조**한다
4. 확인이 안 된 수치는 **카드에 단정적으로 쓰지 않는다.**
   사용자에게 "확인 필요" 항목으로 따로 알려 준다
5. 아직 확정 아닌 것(입법예고, 검토 중)은 카드에 **"검토 중"이라고 명시**하고,
   확정 전에는 발행하지 않는 편이 안전하다
6. 캡션 첫 댓글에 **출처와 기준일**을 적는다

### 뉴스 소재를 수다체로 바꾸기

정보체로 쓰면 이 계정 톤이 아니다. 사실은 그대로 두고 화법만 바꾼다.

| 기사체 | 부모로 |
| --- | --- |
| 9월 15일까지 근로장려금 신청을 접수합니다 | 이번 주 지나면 끝이야 / 9월 15일이 마지막 |
| 독감 무료접종 대상이 14세로 확대됩니다 | 어머, 이거 몰랐어? / 독감 접종 14세까지래 |

## 6. 덱 데이터 구조 (`decks.mjs`)

```js
DECKS.push({
  id: 'C7-paci', type: 'multi',      // 'multi' | 'single' | 'done'(발행완료) | 'draft'
  label: '쪽쪽이',
  gen: true,                          // assets/photos/gen/<ID>-NN.png 자동 연결
  photoDefaults: { photo: '...', pos: '61% center' },   // 실사진을 쓸 때만
  slides: [
    { kind: 'photo', place: '공갈젖꼭지', cat: '육아꿀팁',
      head: ['지호네는 쪽쪽이가 여섯 개래', '쪽쪽이 덜 고생하는 요령 4가지'],
      style: 'bkyu', tone: 'vivid orange',
      scene: 'A Korean mother ... (영어 장면 묘사)' },

    { kind: 'photoBody', lead: '1. 빨다가 뱉으면 거기서 그만이야',
      items: ['억지로 다시 밀어 넣으면 애가 더 크게 울더라고',
              '재우기 전 의식을 다 끝내고 물려야 그대로 잠들어'],
      scene: '...' },

    { kind: 'photoBody', body: ['문장형 본문은 body 로. 2~3문장.'] },
    { kind: 'photoEnd' },
  ],
});
```

### 필드

| 필드 | 뜻 |
| --- | --- |
| `kind` | `photo`(표지) · `photoBody`(내지) · `photoOnly`(글 없는 장) · `photoEnd`(엔딩) |
| `place` / `cat` | 표지 킥커. **정보 분류 그대로** (`공갈젖꼭지 \| 육아꿀팁`). 톤 라벨 금지 |
| `head` | 표지 2행. 1행 장면, 2행 완결된 명사구 |
| `lead` | 내지 헤드라인. 앞의 `1.` `2)` 는 템플릿이 자동으로 별도 칼럼으로 뺀다 |
| `items` | 체크 목록(37px). `body`(문장형 42px)와 **한 카드에 섞지 않는다** |
| `scene` | 이미지 생성용 **영어** 장면 묘사 (8절) |
| `style` | `'bkyu'` 면 B급 감성 프롬프트. **표지에만** |
| `tone` | 배경색 지정. 없으면 자동 로테이션 |
| `bg` | 사진 대신 단색 포스터 카드 |
| `big` | 거대 숫자. `{}` 로 감싼 부분이 작은 단위로 렌더 |
| `ink` | 잉크색 글자 강제 (10절) |
| `zoom` / `pos` | 사진 확대율 / 크롭 위치 |

`lead` 가 두 줄로 넘어가면 숫자 뒤 글자에 맞춰 자동 들여쓰기된다.
**수동 줄바꿈(`\n`)을 절대 넣지 않는다.**

## 7. 문구 규칙

### 표지 — 후킹이 약해지는 네 가지 이유

문구를 쓰기 전에 이 넷을 통과시킨다. 상세는 `hooks.md`.

**① 주제를 소개하고 있다 (약함) vs 장면 안에 들어와 있다 (강함)**
`혁명템이 위험템 됐네` ✗ → `어제 처음 뒤집었는데` ✓
어제 · 오늘 밤 · 이번 주말처럼 **시계가 달린 말**이 붙으면 더 세다.

**② 추상어를 쓰고 있다**
혁명템 · 꿀팁 · 필수템 → **물건 이름과 숫자**로.
`스와들업` `범퍼침대` `근로장려금` `9월 15일` `14세까지`.

**③ 1행이 반쪽짜리 문장이다 — 제일 자주 하는 실수**
카드는 0.5초 만에 읽힌다. 앞뒤 맥락이 없으므로 주어를 빼면 무슨 말인지 모른다.

| 반쪽 | 완결 |
| --- | --- |
| 양치만 하면 소리를 질러 | 우리 애만 칫솔 들면 도망가? |
| 신호 걸리면 바로 알아채 | 차가 멈추면 애가 바로 알아 |

자가 점검: **1행만 떼서 카톡방에 보냈을 때 그대로 말이 되는가?**

**④ 2행이 문법적으로 매달려 있다**
`뒤집기 시작하면 3가지` ✗ → `오늘 밤 뺄 것 3가지` ✓
2행은 **그 자체로 완결된 명사구**여야 한다. 검증기가 이 형태를 자동으로 잡는다.

### 오프닝 패턴 — 세트마다 다른 걸 쓴다

상황 중계 · 코웃음 · 소문 · 질문 던지기 · 남 얘기 · 자기 고백 · 억울함 ·
반전 · 시간 압박 · 경고 · 팁 흘리기 · 공감 한숨.

**같은 패턴 연속 금지.** 14절 기록에서 직전 세트들이 뭘 썼는지 확인하고 고른다.
`hooks.md` 의 사용 기록 표에 매번 한 줄 추가한다. "어머"는 봉인.

### 내지 — 설명하지 말고 수다를 떨어라

내지가 노잼이 되는 이유는 하나다. **정보를 전달하고 있어서**다.
부모방 대화는 정보 전달이 아니라 **경험담 + 판정**이다.

| 노잼 | 재밌음 |
| --- | --- |
| 짧게 쓰는 물건은 중고가 경제적입니다 | 새로 사봐야 반년 쓰고 베란다로 직행이더라고 |
| 아기띠는 착용해보고 구매하세요 | 아기띠는 꼭 매보고 사, 안 그러면 나처럼 후회해 |

네 가지 장치: **① 결과를 그림으로** (베란다 직행, 창고행)
**② 화자가 당해봤다** (나처럼 후회해) **③ 되묻는다** (~잖아 ~거든 ~더라고)
**④ 구체적인 물건과 숫자**.

- 금지: `~합니다` `~하세요` `~권장` `~필요합니다`. **카드는 끝까지 반말 수다체**
- 문장 끝을 매번 다르게: `~해` `~잖아` `~대` `~더라` `~네` `~야?`
- 항목 종결형은 통일. `~하기` 명사형이나 `~니까` `~고` 로 끝내지 않는다 (lead만 명사형)
- 카드는 `1. 2. 3.`, 캡션은 `① ② ③`
- **마지막 줄이 짧게 남으면 줄바꿈으로 끊지 말고 문장 자체를 고쳐** 글자수를 맞춘다.
  단어를 더하거나 어미를 늘리는 방식. 검증기가 55% 미만 줄을 잡아 준다

### 구성은 매번 바꾼다

| 구성 | 언제 |
| --- | --- |
| 순서형 `1·2·3` | 하는 순서가 있는 것 |
| 체크형 `1·2·3` | 병렬 점검 항목 |
| VS형 | 둘로 갈리는 판단 |
| 개수 없음 | 사실 하나가 핵심일 때 (한장) |

### 공감형 세트 — 정보가 아니라 마음이 목적일 때

`남편 육아분담` `독박육아` 같은 주제:

- **누구도 탓하지 않는다.** 브랜드 계정이 배우자를 욕하면 절반이 등을 돌린다
- 탓하는 대신 **안 보이던 일에 이름을 붙인다** ("기획노동", "티 안 나는 육아")
- 항목은 지시가 아니라 **장면**으로. "~해야 한다" 금지, "~하고 있잖아" 로
- 마지막에 **나눌 방법 한 가지**는 넣는다. 하소연으로만 끝내지 않는다

## 8. 이미지 생성

**슬라이드마다 영어 `scene` 을 쓴다.** 한국어 카피를 그대로 넘기면
이미지 모델이 글자를 그려 넣거나 엉뚱하게 해석한다.

생성한 이미지는 `assets/photos/gen/<덱ID>-NN.png` 에 저장한다
(`NN` = 01부터, `photoEnd` 제외). 덱에 `gen: true` 만 있으면 자동으로 붙는다.

### 기본 스타일 — 일본 광고 포스터 (내지 전부 + 기본 표지)

```
Japanese advertising poster aesthetic, bold and eye-catching. One clear subject,
exaggerated expressive emotion, dynamic sense of motion. Saturated flat
single-colour background, crisp studio lighting, high contrast. Photographic and
real, not illustration, not 3D render. Korean people, Korean home or Korean
clinic setting. Vertical 4:5 composition. Subject placed in the upper two thirds.
The lower third must stay visually calm and uncluttered for text overlay.
Absolutely no text, no letters, no numbers, no logos, no watermark, no signature.
```

### B급 감성 표지 — `style: 'bkyu'`

표지 후킹을 이미지로도 밀어야 할 때. 쇼와 시대 일본 잡지 광고 / 심야 홈쇼핑 톤.
**세련된 게 아니라 촌스럽고 과장돼서 스크롤이 멈추는 쪽.**

```
Showa-era Japanese B-movie poster and late-night TV shopping advert aesthetic.
Deliberately cheap, loud and campy - not sleek, not tasteful, not minimal.
One subject dead centre, filling the frame, staring straight down the lens with a
wildly exaggerated deadpan or desperate expression. Hard direct on-camera flash,
slight overexposure on the face, harsh drop shadow thrown onto the wall behind.
Punchy oversaturated colours, mild colour fringing, faint film grain and a whisper
of print halftone, like a 1980s magazine ad scan. Saturated flat single-colour
studio backdrop, no props beyond the ones described. Photographic and real,
live-action, not illustration, not 3D render, not anime. Korean people, Korean home setting.
Vertical 4:5 composition. Subject in the upper two thirds. The lower third must
stay visually calm and uncluttered for text overlay. Absolutely no text, no
letters, no numbers, no logos, no watermark, no signature.
```

B급 포인트 세 개: **정면 직광 플래시**(얼굴 살짝 날아가고 벽에 그림자가 뚝 떨어짐) ·
**과채도 + 인쇄 망점** · **정면 응시 무표정**. 세련되게 뽑히면 실패다.
그럴 땐 `make it cheaper and louder, like a 1980s Japanese magazine ad` 를 덧붙인다.

**표지에만 쓴다.** 내지까지 B급으로 가면 세트가 산만해지고 글자가 안 읽힌다.

### 지켜야 할 것

- **비율은 4:5 세로.** 글자가 들어간 이미지는 버리고 다시 받는다
- **하단 3분의 1은 비운다.** 그 자리에 카드 텍스트가 얹힌다
- 한 세트는 **같은 배우 · 같은 조명**으로. 카드 사이가 붕 뜨면 안 된다
- 배경색은 카드마다 다르게 (`TONES` 로테이션). 피드가 한 색으로 몰리지 않게
- 아이 얼굴이 정면으로 크게 나오는 구도는 피한다
- 표지 해상도를 양보하지 않는다. 표지에서 세트 전체가 갈린다

### 도구가 한 번에 한 장만 뱉을 때

**표지는 단독, 내지는 2×2 격자**로 요청한다.
격자 이미지를 받으면 `adopt.mjs --grid=2x2` 가 읽기 순서(좌상→우상→좌하→우하)로
쪼개서 붙인다. 격자 칸은 512×640 정도라 1080 기준 2.1배 확대되므로
**표지에는 쓰지 않는다.**

### 관련 스크립트

```bash
node genimage.mjs --deck=<ID> --dry      # 프롬프트만 출력
node genimage.mjs --deck=<ID> --batch    # 세트 전체를 한 번에 요청하는 프롬프트
node genimage.mjs --deck=<ID> --sheet    # 붙여넣기용 프롬프트 문서(md) 생성

node adopt.mjs --deck=<ID> 표지.png                    # 순서대로 4:5 크롭 후 배치
node adopt.mjs --deck=<ID> --grid=2x2 --from=2 격자.png # 격자를 쪼개 2장째부터
```

이미지를 직접 생성할 수 있으면 위 프롬프트로 만들어 `gen/` 에 바로 저장하면 된다.
API로 갈 때 키는 `.env.local` 의 `GEMINI_API_KEY` — **채팅·커밋에 절대 넣지 않는다.**
구글 생성 이미지에는 SynthID(비가시 워터마크)가 항상 들어가며 제거할 수 없다.

## 9. 레이아웃 — 건드리지 말 것

| 요소 | 위치 | 크기 |
| --- | --- | --- |
| 표지 킥커 + 헤드라인 | 하단 17% | 헤드라인 80px / 킥커 27px |
| 내지 본문 블록 | **하단 24%** | lead 50px · items 37px · body 42px |
| 계정명 `@bumoro.kr` | 좌상단 64/56 | 30px |
| 넘버링 `2 / 6` | 우상단 | 25px, 표지에는 없음 |

내지가 하단 24%인 이유: 인스타 **리포스트/스레드 UI**(친구 태그 말풍선 ·
프로필 스티커)가 하단 20%를 덮는다. 그 아래로 내려가면 글자가 잘린다.

음영은 `generate.mjs` 가 사진마다 자동 계산한다. **손대지 않는다.**
표지는 위·아래만 살짝(사진이 선명해야 함), 내지·엔딩은 전면 균일 톤다운(글자가 주인공).

## 10. 글자색 — 사진 밝기가 정한다

사진 평균 휘도가 **0.72를 넘으면** 흰 글자를 포기하고
**잉크색 글자 + 흰 베일**로 자동 전환된다 (`.ph.light`).
밝은 사진을 흰 글자에 맞춰 검게 누르면 "표지는 선명하게" 규칙이 깨지기 때문이다.

휘도 0.6~0.72는 자동 판정이 애매하다. 흰 글자로 가면 배경색이 죽는 사진
(파스텔 배경 등)은 `ink: true` 로 잉크 글자를 강제한다.

## 11. 검증 게이트 — 넷 다 조용해야 커밋

```bash
node generate.mjs --deck=<ID>
```

1. **가독성 검사** — 명도대비. 본문 4.5:1, 큰 글자 3.0:1. `전부 통과.` 가 떠야 한다
2. **줄 채움 점검** — 가로폭 55% 미만인 줄. 뜨면 **문장을 고쳐** 채운다
3. **표지 문구 점검** — `~하면 3가지` 처럼 개수가 절 뒤에 매달린 형태
4. **세이프존** — 표지 외 카드의 텍스트 아래끝이 1053px(78%)을 넘는지

추가로 **구성 점검**이 세트별 항목 수를 출력한다. 직전 세트와 겹치면 구성을 바꾼다.

**하나라도 걸린 채로 커밋하거나 사용자에게 전달하지 않는다.**

산출물: `public/instagram/<ID>-NN.png`, `<ID>.zip`, `ALL-cards.zip`, `preview.html`

```bash
node generate.mjs            # draft 제외 전부
node generate.mjs --multi    # 여러장 세트만
node generate.mjs --single   # 한장 세트만
```

## 12. 캡션 (`captions.md`)

```
[본문]      후킹 한 줄 + 이모지 1개 → 정보 3~5줄(① ② ③) → 질문으로 마무리
[첫 댓글]   출처 · 기준일 · 주의사항 · 부연
[해시태그]  8~10개, 마지막은 항상 #부모로
```

- 이모지는 **주제마다 다른 것 하나만**. 🩵 반복 금지
- 카드는 반말, **캡션 본문은 존댓말**
- 한장 세트는 카드에 못 담은 정보를 캡션 본문이 전부 진다
- 뉴스 소재는 첫 댓글에 **출처와 기준일**을 반드시 적는다

## 13. 의료 소재 · 사실 확인 · 보안

### 의료

발열·약·피부처럼 진료 영역에 걸치는 주제는 **카드에 수치와 용량을 쓰지 않는다.**
"38도부터", "몇 ml" 같은 기준은 아이마다 달라 카드가 책임질 수 없다.

- 카드에는 **판단 주체를 병원으로** 넘기는 문장을 쓴다
  ("기준이랑 용량은 접종한 병원에서 정해준 대로 가고")
- 마지막 항목은 **병원에 가야 하는 신호** 목록으로 닫는다
- 캡션 첫 댓글에 "부모들이 나눈 경험이지 진료 지침이 아니다" 를 명시한다
- 방에서 나온 수치를 옮길 때는 "방에서는 ~라고 안내받았다는 분이 많았지만
  아이마다 다르니 병원 안내를 따르라" 형태로만 쓴다

### 사실 확인

정책·금액·날짜는 검색 스니펫만으로 단정하지 않는다(5절).
확인이 안 된 수치는 사용자에게 "확인 필요"로 따로 알리고, 카드에는 단정적으로 쓰지 않는다.

### 보안

- API 키·토큰·비밀번호를 **채팅 출력·커밋·푸시되는 파일에 절대 넣지 않는다**
- 키는 `.env.local`(chmod 600, gitignore)에만 둔다
- 서비스 계정 JSON은 파일이나 환경변수로 받는다. 채팅에 붙여넣게 하지 않는다
- 커밋 전후로 히스토리에 키 문자열이 없는지 확인한다
